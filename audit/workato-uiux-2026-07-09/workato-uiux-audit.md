# Workato/Worlato UI/UX 분석 메모

분석 기준일: 2026-07-09

## 확인한 화면

- 대시보드 개요: 운영 지표, 상태 카드, 필터, 연결 상태
- 활동 감사: 날짜 그룹 타임라인, 이벤트 상세, 도움말 패널
- 프로젝트 목록: 워크스페이스 레일, 프로젝트 카드, 최근 작업 재진입
- 생성 메뉴: 레시피, 연결, 테이블, 에이전트, MCP 서버, 앱 생성 진입점
- 새 프로젝트/업무 시작: 레시피, 에이전트, MCP 서버, 앱, 템플릿, 처음부터 시작하기
- 레시피 에디터: 빌드 탭, 연결/버전/테스트/설정 탭, 우측 상태 패널
- 전체 화면 빌더: 캔버스 중심 구성, 우측 Copilot, 저장/종료 액션
- 테스트 실행/성공: 단계별 상태, 성공/스킵 표시, 다음 액션
- AI Agent 상세: Build/Test 모드, 이벤트/스킬/MCP/자율성 설정

## 우리가 반영할 만한 패턴

### 1. 통합 생성 메뉴

Workato 프로토타입은 상단의 단일 생성 버튼에서 여러 오브젝트를 시작하게 만든다. 우리 콘솔도 사이트, 세션, 자동화, 테스트 실행, 증빙 패킷, 커넥터, 문서 IDP 시작점을 흩어두기보다 통합 생성 메뉴로 묶는 것이 좋다.

반영 방향:
- `새로 만들기` 메뉴를 전역 액션으로 추가
- 항목: 사이트 등록, 로그인 세션 등록, 자동화 생성, 템플릿에서 시작, 테스트 실행, 증빙 패킷 생성
- 각 항목에 준비 조건을 표시: 예) 사이트 필요, 세션 필요, SecretRef 필요
- 생성 이후 다음 단계로 바로 이어지는 CTA 제공

효과:
- 사용자가 "무엇부터 해야 하는가"를 덜 고민한다.
- 온보딩과 일반 운영 액션을 같은 문법으로 배울 수 있다.

### 2. 시작점 선택 화면

새 프로젝트 모달의 "레시피 만들기 / 에이전트 만들기 / MCP 서버 만들기 / 앱 만들기 / 처음부터 시작하기" 구조는 강하다. 우리 제품에서는 도메인에 맞춰 아래처럼 바꾸는 것이 좋다.

반영 방향:
- 브라우저 업무 자동화
- 문서/IDP 자동화
- API/커넥터 자동화
- AI Agent 자동화
- 템플릿에서 시작
- 처음부터 설계

각 시작점에는 "필요 준비물"과 "다음 단계"를 함께 보여준다. 예를 들어 브라우저 자동화는 사이트 등록과 로그인 세션 등록이 필요하다는 것을 같은 카드 안에서 알려야 한다.

### 3. 전체 화면 Automation Studio

전체 화면 빌더는 집중도가 좋다. 우리 `Scenario Studio`도 일반 콘솔 안의 폼처럼 보이기보다, 자동화 설계 순간에는 빌드 전용 화면으로 전환되는 편이 낫다.

반영 방향:
- 상단: 자동화 이름, 상태, 저장, 테스트, 종료
- 좌측/중앙: 플로우 캔버스 또는 단계 목록
- 우측: AI 생성/수정 패널, 준비도, 보안 경고, 증빙 상태
- 탭: 설계, 테스트, 연결, 버전, 설정

단, Workato처럼 단순 빌더에만 집중하면 우리 제품의 차별점인 증빙/감사/보안 컨텍스트가 약해질 수 있다. 우측 패널에는 반드시 readiness와 evidence 정보를 같이 둔다.

### 4. 테스트 실행 UX

테스트 실행 화면은 매우 직접적이다. 트리거 대기, 단계 실행, 성공/스킵/실패, 다음 액션이 한 화면에 나온다. 우리도 실행 결과를 JSON/로그 중심으로만 보여주면 안 된다.

반영 방향:
- 테스트 시작 후 진행 상태를 단계별로 표시
- 각 단계에 성공, 실패, 스킵, 대기 상태 표시
- 실패 시 원인, 재시도, 세션 재등록, SecretRef 확인 같은 복구 CTA 제공
- 성공 시 "증빙 확인", "운영 등록", "스케줄 설정"으로 이어짐

### 5. 템플릿 상세 화면

템플릿 상세에서 앱, 단계 미리보기, 사용량, 예상 시간을 보여주는 방식은 채택할 가치가 높다. 우리 커넥터/시나리오 템플릿도 단순 목록보다 "실제로 어떤 자동화가 만들어지는지"를 먼저 보여줘야 한다.

반영 방향:
- 템플릿 카드 클릭 시 상세 패널 제공
- 단계 미리보기: 트리거, 액션, 반복, 조건
- 필요한 준비: 사이트, 세션, SecretRef, 권한
- 예상 설정 시간과 테스트 가능 여부 표시
- CTA: 이 템플릿으로 자동화 만들기

### 6. 활동 감사 타임라인

활동 화면은 날짜별 타임라인이 이해하기 쉽다. 우리 제품의 감사/운영 로그는 테이블 중심이어야 하지만, 관리자 첫 화면이나 자동화 상세 안에서는 타임라인 요약이 더 빠르게 읽힌다.

반영 방향:
- 최근 변경, 테스트, 배포, 실패, 증빙 생성 이벤트를 날짜 그룹으로 표시
- 각 이벤트에 행위자, 대상, 결과, 관련 증빙 링크 표시
- 관리자용 상세 테이블은 유지하되, 요약 타임라인을 병행

### 7. 워크스페이스/환경 컨텍스트

상단의 워크스페이스 선택, 샌드박스 배지, 환경 진입점은 실무적으로 좋다. 우리 제품은 tenant/site/environment 경계가 중요하므로 더 강하게 써야 한다.

반영 방향:
- 전역 헤더에 현재 테넌트/워크스페이스와 환경 표시
- sandbox, staging, prod, controlled-prod 같은 운영 모드 배지 표시
- 위험 액션 전에는 현재 환경을 재확인

### 8. AI Agent 상세 구조

AI Agent 화면의 Build/Test 전환과 이벤트, 스킬, MCP, 자율성 패널은 우리 AI 자동화/에이전트 구성에 맞다.

반영 방향:
- Agent/Scenario 상세에서 Build/Test segmented control 제공
- 이벤트, 도구, MCP, 지식, 자율 실행, 승인 정책을 별도 섹션으로 정리
- 각 섹션에 보안 상태와 RBAC 요구 조건 표시

## 그대로 가져오면 안 되는 점

- 카드가 크고 여백이 넓어 운영 콘솔의 정보 밀도가 떨어질 수 있다.
- Workato식 프로젝트/레시피 중심 IA는 우리 도메인의 사이트, 세션, 증빙, 정책 개념을 가릴 수 있다.
- 파란색 강조가 많아지면 상태/위험/증빙 신호가 약해질 수 있다.
- 프로토타입의 일부 영문/국문 혼용, 이모지성 아이콘은 엔터프라이즈 제품 톤에 맞지 않는다.
- 전체 화면 빌더만 강조하면 관리자/보안 전문가가 필요한 감사 가능성과 통제 근거가 뒤로 밀릴 수 있다.

## 우선순위

### P0

1. 전역 `새로 만들기` 메뉴
2. 첫 자동화 시작점 선택 화면
3. 테스트 실행 상태 패널
4. 자동화 생성 후 증빙 확인까지 이어지는 다음 단계 CTA

### P1

1. Automation Studio 집중 모드
2. 템플릿 상세/미리보기 패널
3. 활동 감사 타임라인 요약
4. 워크스페이스/환경 배지 강화

### P2

1. AI Agent 상세의 Build/Test 구조
2. 단축키 힌트
3. 시각 스타일 세부 조정

## 결론

가장 크게 가져올 것은 시각 스타일보다 여정 설계다. Workato 프로토타입은 "생성하기", "시작점 선택", "빌더", "테스트 결과", "다음 액션"을 한 호흡으로 묶는다. 우리 제품은 여기에 사이트 등록, 로그인 세션, SecretRef, RBAC, 증빙 패킷을 자연스럽게 끼워 넣어야 한다.

따라서 다음 개발 순서는 전역 생성 메뉴와 온보딩 시작점 선택을 먼저 만들고, 그 다음 테스트 실행 상태와 증빙 확인 CTA를 붙이는 것이 가장 효과적이다.
